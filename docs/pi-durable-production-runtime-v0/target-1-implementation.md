# Target 1 — production workflow runtime core implementation evidence

> **Status: READY** for the opt-in Target 1 core only. It is not wired into Pocket production; the full Pocket suite retains one known, unrelated macOS path-alias failure.

## Scope and architecture

Single-writer implementation; no commit, restart, frozen spike rewrite, UI, Target 2 wait/event/timer API, agent API, or Pi core patch. Production files are `packages/workflow-runtime/core/index.ts` (public definition, engine, Task kernel, operation transitions and invocation), `run-control.ts` (unified invocation-local stop arbitration and caller-scoped observation), and `identity.ts` (canonical admission and collision-safe tuple identity). Static `workflowRuntimeExtension`/`WorkflowRuntimeTask` remain a convenient default; `createWorkflowRuntimeKernel()` supplies a **per-host isolated definition registry and native Task handler**. Install its extension before Harness.open, then use `kernel.createEngine(harness)`. Missing definitions park generically and permit stop; registering the exact definition and activating the engine wakes the run. No automatic migration.

Pi native Task checkpoint is live execution authority; native selected/final outcome is terminal authority. The workflow run document is an atomic admission locator and bounded inspection projection, not a replacement scheduler. Journal Entries are historical. Central `runtime.commit` rereads latest checkpoint and atomically writes operation projection, journal, and next Pi Task state. Ordinary terminal paths close operation admission before draining effects; native aborted selection for stop occurs *before* owned-descendant cleanup. Inspection derives terminal status from native Task and exposes native root Task ID plus `pending`/`native-settled` cleanup state, **not** an invented cleanup-success claim. Native child Task outcome is inspectable for cleanup failures. Projection summarizes at most 64 operations, discloses eviction count; journal/checkpoint retain complete semantic history while live. No attempt-history cap silently discards unknowns.

Promoted concepts: latest-checkpoint Transition Writer, invocation drain/closed admission, stable named attempts, operation unknown/reconcile/retry, Pi native ownership/cascade, cold-process crash fixtures. Rewritten for production: canonical explicit-run admission, namespace/kinds, per-host factory, inspection projection, error contract. Deferred: event ingress, wait/sleep/timer, agents and integrations, migration, custom ownership/scheduler. Adapter surface after stop-control extraction: 1,517 lines public kernel, 323 lines run control, and 52 lines identity; 3,636 core-test lines plus 401 crash-worker lines (`wc -l`). The large kernel and test file remain reviewability risks; only identity and the stop arbiter are extracted to keep transition semantics on a verified seam.

## Pocket composition smoke (test-only)

`test/workflow-runtime-app.test.ts` proves the opt-in core can use a real `PocketApp` Harness without changing the served interpreter. `OpenOptions.testExtensions` is a test-only seam: Pocket installs the supplied extension after normal extension loading and before `Harness.open`; ordinary app launches omit it. For each app lifetime, the test creates one core kernel and engine, registers one `step.do` workflow on that engine, runs and inspects it, selects `stopped`, closes the core engine and app, then reopens the same data directory with a fresh kernel/engine and inspects the stopped run. It verifies the completed operation remains recorded and the callback is not repeated. `PocketApp.workflowEngine` remains unchanged; no user-facing route or production core registration is added.

## Residual limits

No Target 2 wait/event/timer, agent, UI, or production workflow registration is wired into Pocket. Native cleanup responsibility is exposed by root Task ID, not aggregated child failure details in the workflow inspection. Definition compatibility uses explicit author-managed version; registered old versions can be activated intentionally. The default static extension uses a process-global registry for backward compatibility with its public seam; **new deployments must use `createWorkflowRuntimeKernel()` for host isolation**. Operation histories are not arbitrarily truncated; very long-running runs can grow the checkpoint until terminal retirement. The independent code review was READY; this is not a separate architecture review. The full Pocket suite's path-alias failure remains outside Target 1.
